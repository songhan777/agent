# 学习指南：从前端开发到 Electron Agent

适用基础：你已经会 JavaScript 和 React/Vue，还没有 Electron 项目经验。模板采用 React，你可以先集中学习桌面进程和工具执行；框架差异不会改变主进程、preload 与 IPC 的职责。

学习产物是一套能解释、能修改、能排障的桌面文件助手。每一步先运行现有实现，再独立做一个小改动，最后制造一种异常并验证处理结果。

## 第 0 步：先建立可重复的运行环境

### 阅读

- 根目录 `README.md`：运行方式和演示边界。
- `package.json`、`tsconfig.json`、`electron-builder.yml`：结合 `docs/CONFIG_EXPLAINED.md` 阅读。
- `examples/workspace`：这个目录是工具的输入数据，不是模板自己的业务逻辑。

### 实验

1. 先按 README 检查 Node.js、npm 与 pnpm；环境未就绪时，可先打开 Windows 分发目录版观察交互。开始修改源码前，再安装依赖并运行 CLI 演示。
2. 运行桌面应用，选择相同目录，提交相同问题。
3. 在示例目录新增一个普通文本文件，重新执行并观察日志变化。
4. 运行类型检查、自动化测试和注释检查，记录命令用途。

### 验收

你能说明“安装依赖需要网络”和“运行 demo 不需要模型服务”的区别；能找到项目根目录、示例输入目录和构建产物；能区分开发运行与打包后运行。

## 第 1 步：通过共享契约补齐 TypeScript

### 阅读

`packages/shared/src/contracts.ts`。

关注 `RunMode`、`TaskStatus`、`TaskEvent`、`TaskSnapshot`、`AppState` 与 `DesktopBridge`。先画出这些类型之间的包含关系，再到使用位置搜索类型名称。

### 理解

- 联合类型为何适合状态和事件种类。
- 可选字段 `answer?` 和 `error?` 表达什么。
- 为什么 IPC 状态采用字符串时间而不是复杂的运行时对象。
- 为什么页面契约没有 API Key、AbortController 和文件句柄。
- 为什么 TypeScript 无法阻止运行时传入错误的字符串或对象。

### 实验

给任务快照增加一个可选的 `durationMs` 字段，再思考它应该在哪个位置计算、哪些状态有意义。不要先修改界面；先确定数据由谁负责产生。

### 验收

你能顺着编译错误补齐字段使用位置，也能解释类型检查与运行时校验分别解决什么问题。

## 第 2 步：用文件工具学习 Node.js

### 阅读

`packages/core/src/tools.ts`，顺序建议为：

`TOOL_LIMITS` → `checkCancelled` → 参数校验 → `resolveSafe` → `walk` → 三个工具 → `invoke`。

### 理解

- `fs/promises` 与 `path` 的基本用途。
- 相对路径和真实路径有什么区别。
- 为什么不能使用简单的字符串前缀判断目录归属。
- 为什么用 `try/finally` 关闭文件句柄。
- 为什么工具返回截断标记与跳过数量。
- 为什么取消检查需要放在多个异步步骤之间。

### 实验

依次使用普通文件、中文名称、空目录、超过读取上限的文件和不存在的文件。再尝试传入 `../`、绝对路径和未知参数，查看校验产生的结果。

扩展练习：给搜索工具增加“只匹配指定扩展名”的选项。需要同时修改参数白名单、运行时校验、实际筛选和工具定义；不能只修改 TypeScript 类型。

### 验收

你能说明一次读取经过了哪些边界检查，能解释截断结果为何不能被描述成完整扫描，也能保证新增筛选不绕过原有目录权限。

## 第 3 步：先在 CLI 中理解 Agent

### 阅读

`packages/core/src/index.ts` 中的 `runAgent`、`runDemo`、`runOpenAI`、`requestModel`，以及 `apps/cli/src/index.ts`。

### 理解

- `runAgent` 接收什么输入，通过什么方式输出事件与最终结果。
- demo 模式如何确定性地安排工具调用。
- 真实模式怎样把工具声明交给模型，再执行模型提出的调用。
- 模型提出一个工具名称，与程序真正允许执行该工具，是两个步骤。
- 最大步数、工具输出限制和请求取消分别控制什么。

### 实验

1. 对小型目录运行 demo，按顺序列出事件。
2. 修改问题，再检查哪些行为由 demo 规则决定。
3. 在任务执行中按 `Ctrl+C`，追踪取消信号流向。
4. 在测试中模拟未知工具、格式错误的参数和模型请求失败。

真实模型实验需要自己的密钥和可用模型。未配置时先完成 demo 和本地测试；不要把 demo 输出误认为模型能力评测。

### 验收

你能独立画出工具调用循环，并解释“最终文字回答”和“实际工具结果”之间的关系。CLI 运行出现问题时，能判断错误来自参数、文件工具还是模型交互。

## 第 4 步：学习 Electron 主进程和 preload

### 阅读

依次阅读 `apps/desktop/src/main/index.ts` 的应用入口和 IPC 注册，再阅读 `apps/desktop/src/preload/index.ts`。

### 理解

- 应用创建窗口与页面渲染不是同一个生命周期。
- 主进程负责打开系统目录选择框。
- preload 通过 `contextBridge` 暴露少量命名函数。
- 页面不需要原始 `ipcRenderer`，也不应该自行读任意文件。
- IPC 请求如何校验调用来源与输入参数。
- 关闭窗口、退出应用时如何清理订阅与任务。

### 实验

沿着“选择目录”按钮完整追踪一次请求：React 调用 → preload → IPC handler → 系统对话框 → 新状态 → 页面。

扩展练习：增加一个“读取应用版本”接口。先添加契约与通道，再添加主进程处理和 preload 方法，最后在页面展示。

### 验收

你能在不暴露原始 IPC 的情况下增加桌面能力；能解释每个步骤放在对应进程的理由；知道修改主进程或 preload 后需要重启开发应用。

## 第 5 步：任务管理、取消和历史记录

### 阅读

`apps/desktop/src/main/task-manager.ts` 中的任务管理与存储实现，同时对照 `contracts.ts` 的状态定义，再读 `tests/task-manager.test.ts`。

这份测试覆盖两任务并发与第三任务排队、取消后的迟到结果、历史恢复、任务目录固定、输入及容量校验和快照隔离。阅读时先看断言要证明什么，再追踪受控执行器如何制造对应场景。

### 理解

- 为什么同一时间只允许有限数量任务运行。
- 排队任务取消与运行任务取消有什么区别。
- AbortController 为什么留在后台，而不进入持久化快照。
- 当前选择的目录与某个任务创建时的目录为什么分别保存。
- 为什么重启后不能继续显示旧任务“正在运行”。
- 历史回放为什么不等于从中断位置继续执行。

### 实验

1. 连续创建超过并发上限的任务，观察队列。
2. 取消一个排队任务，再取消一个运行任务。
3. 创建任务后切换工作目录，检查旧任务的目录是否变化。
4. 正常退出并重开应用，观察历史状态。
5. 在测试环境中制造无效历史文件，检查启动是否有明确处理。

### 验收

你能为每种状态列出合法的后续状态；任务不会互相混用日志；取消后不会被迟到的结果改成完成；能定位历史记录实际存在哪里。

## 第 6 步：连接 React 界面

### 阅读

`apps/desktop/src/renderer/main.tsx` 和 `styles.css`，先看全局类型与 `App`，再看任务卡片、事件卡片和样式。为了使每个非空行的注释保持直观，页面使用 `createElement` 的别名 `h` 构建元素；它仍然是 React，并使用常规 Hooks。

### 理解

- 首次状态获取与后续状态订阅如何配合。
- `revision` 为什么能帮助避免旧响应覆盖新状态。
- `useEffect` 为什么返回取消订阅函数。
- 界面保存用户输入，后台保存任务事实，两者怎样分工。
- 按钮禁用、错误提示、空状态和任务进度怎样帮助用户判断下一步。

### 实验

增加一种任务筛选方式，例如“全部 / 运行中 / 已结束”。保持过滤只影响展示，不删除后台任务。

观察已有的工具详情折叠行为，再增加“只看工具事件”的过滤选项，检查长文本是否影响其他任务的可读性。

### 验收

反复挂载页面不会重复接收事件；旧响应不会覆盖最新状态；界面的选中项和任务状态不会互相混淆。

## 第 7 步：性能与分发

### 阅读

`scripts` 中的开发和构建脚本、`electron-builder.yml`，以及主进程中状态广播和持久化的实现。

### 实验

1. 构建后关闭开发服务器，使用 `pnpm start` 运行。
2. 生成 `package:dir` 或 Windows ZIP 产物，ZIP 必须完整解压，再从实际分发目录启动。
3. 记录启动时间、任务数量、事件数量和测试设备。
4. 让历史列表变长，检查完整快照广播的大小与页面更新耗时。
5. 检查哪些文件进入分发产物，哪些开发资料没有进入。

修改后先运行 `pnpm build`，再运行 `pnpm test:desktop` 验证生产页面；使用 `pnpm test:desktop --dev` 可以验证开发页面。打包目录验证通过 `AGENT_LAB_EXECUTABLE` 指定实际 exe。它们使用原生离屏截图检查真实 Electron 页面；不要把离屏运行结果当作普通 GPU 模式的性能测量。

### 扩展练习

在测量发现问题后，任选一项修改：状态事件批量推送、按任务发送增量状态、历史分页或把重计算迁移到独立执行位置。

### 验收

你能用同一环境的修改前后数据解释优化收益；能分清 build、start 和 package；能明确指出签名、自动更新和其他平台哪些尚未实现或验证。

## 第 8 步：真实模型、上下文与后续技能

先为真实模型准备几项固定任务，例如“概览目录”“查找任务状态定义”“解释入口函数调用关系”。保留输入目录版本和预期证据，比较实际工具调用与回答。

然后按需要扩展：

| 技能 | 建议练习 | 验收重点 |
|---|---|---|
| 上下文管理 | 为长任务增加结构化摘要 | 用户限制、已完成步骤和未完成事项没有丢失 |
| MCP | 把现有只读搜索工具封装成 MCP 服务 | 接入协议后仍执行参数和目录权限校验 |
| 文件修改 | 在副本目录中生成并展示 diff | 用户能检查修改，失败不会留下无解释的部分状态 |
| 浏览器自动化 | 先操作自己制作的练习页面 | 有明确等待条件和结果验证 |
| 多智能体 | 分析不同文件后汇总 | 比较单 Agent 和多 Agent 的成本与效果 |
| 自动更新 | 使用测试发布渠道做两个版本升级 | 保留用户数据，并验证更新失败情况 |
| AI Coding 架构 | 对照一个开源工具追踪任务循环 | 能说明实现差异及设计取舍 |

这些是扩展作业，不是模板已经具备的功能。

## 把项目整理成应聘证据

完成学习后，准备以下材料：

- 一段可复现的演示：创建任务、工具执行、取消和历史回放。
- 一张自己画的架构图，标注进程边界与依赖方向。
- 一次故障记录，写清复现步骤、定位证据、修复与验证。
- 一份性能实验，包含环境、数据规模和修改前后结果。
- 一次自己完成的功能扩展，解释代码变化和测试覆盖。

逐行注释用于帮助读懂模板。完成一轮学习后，建议另开练习副本，只保留解释关键设计的注释，尝试独立实现一个模块；这样可以检查自己是否已经理解，而不只是跟读。
